# dsh-weixin 实施方案

## 目标

将 Hermes Agent 的 Weixin/iLink 通信适配器移植为 DSH 消息渠道插件：微信只负责消息入口/出口，DSH 负责会话、Agent、工具、权限和任务生命周期。

## 边界

### 移植到插件

- iLink 请求客户端和消息轮询；
- 绑定/登录状态管理；
- 文本、图片、文件消息的规范化；
- 发送、分段、重连、退避和限流处理；
- Weixin 会话 ID 与 DSH conversation ID 映射。

### 不移植

- Hermes Agent runtime；
- Hermes tool registry、prompt、CLI 和 session store；
- Hermes 独有的模型/权限系统。

## 目标架构

```text
Weixin/iLink -> dsh-weixin transport -> DSH Channel API
                                      -> DSH Conversation/Agent/Tools
```

插件内部按 transport、message、session、security 分层；先使用本地接口抽象，避免把未知的 DSH 私有 API 写死。

## 里程碑

1. **M0 审查**：固定 Hermes commit，核对许可证/依赖，读取 DSH 插件入口；用真实账号验证 iLink 能力。
2. **M1 文本闭环**：绑定、收文本、调用 DSH Agent、发文本；消息去重与断线恢复。
3. **M2 任务控制**：长任务状态、任务 ID、取消、长消息分段和审计。
4. **M3 安全策略**：发送者白名单、工具分级、一次性确认码、敏感输出脱敏。
5. **M4 媒体**：图片/文件/截图/diff。
6. **M5 原生 UI**：连接状态、配置、白名单、权限策略和日志。

## 关键设计

- transport 不直接执行 DSH 工具；
- sender 使用稳定用户 ID，不使用昵称做鉴权；
- 每条入站消息以 message ID 幂等；
- session 文件只留在用户本机；
- 危险动作由 DSH 权限层确认，而不是信任微信文本。

## 验收顺序

先通过单元测试验证配置、白名单、去重、会话映射，再接真实 Hermes transport；最后使用测试账号完成微信 -> DSH -> 微信闭环。当前阶段不承诺真实账号可用，因为 iLink 能力可能受账号、地区、限流和服务端策略影响。

## 当前状态与后续方向（2026-10-26 更新）

M0–M5 全部达成并超出原计划：文本/媒体/语音闭环在真实账号上稳定运行；安全默认（白名单默认全拒、幂等、脱敏）落地；原生 UI 含扫码卡片、状态卡与 7 页签设置卡。npm 已发布 **0.9.3**（回合中流式推送工具变化、出站限速接线、`/cancel` + 工具审计、状态卡自刷新、发版清单守卫、轮内派发改造全部进入该版），插件市场 PR 仍等维护者合并 awesome-dsh-plugin#7426。0.9.3 之后新增出站语音，真机复测结论已出：**iLink 服务端接受机器人 `voice_item`（ret=0）但不投递**，与 2026-06 的实测一致，故 `voiceOutbound` 默认改回关（代码保留，服务端放开后一键打开）。测试 411 全绿。逐项待办见 `docs/progress.md` 顶部「未完成 / 待办」。

里程碑之外已经完成的方向（源自对 dsh-im 的学习移植）：

- **对话体验**：忙时消息排队/插话（`busyMessageMode`、`/steer`）；超时不再丢答案（先告知、后补发，context_token 一次性约束下用 `refreshConfig()` 取新 ticket）。
- **Agent 语境**：可选 `sourceContext` 在 prompt 前附 `<weixin_source …/>` 来源块。
- **设置 UI**：真 tablist + 下载设置原子保存（暂存→保存/还原条）；同一设置卡同时挂在插件页与宿主 Settings 导航（`settings.section`，order 22）。
- **语音识别开箱可用**：仓库自带 `bin/asr-bridge.py`（双引擎：Apple Silicon 走 mlx-whisper GPU，其它平台走 faster-whisper CPU），用户下载插件后只需 `pip install` 一个引擎、在设置页点一次下载，不再需要自己写服务端。实测热调用 0.29s（mlx/GPU）对 5.3s（Rosetta CPU），中文默认出简体，非语音返回空而不是编造。
- **发布工程**：图标/hero 资产随包分发（manifest 引用的路径必须同时进 npm files 与安装器 COPY_ENTRIES）；desktop profile 现依赖 registry semver（`dsh-plugin-weixin@^0.9.3`），不再钉在 /tmp 的 tarball 上；`package.json` 与 `package-lock.json` 的版本一致性由发版 preflight 强制，漂移会在发版时被拒绝而不是悄悄发出去。设置卡「来源信息」显示的是 profile **声明的** spec，不是磁盘上的字节，所以安装器会提示把残留的 `file:…tgz` 换成 `^<版本>`。

### 候选后续

1. **依赖源切换（2026-10-23 已完成）**：desktop profile 已改为 `dsh-plugin-weixin@^0.9.5`，锁文件同步（`pnpm-lock.yaml` 的 specifier/version/integrity 都与 registry 一致）。清单漂移由发版脚本兜住：`bin/release.mjs` 的 preflight 会核对 `package.json` 与 `package-lock.json` 的两处版本字段，不一致就拒绝发版；`bin/install.mjs` 在 profile 仍声明 `file:…tgz` 时会打印该换成哪条 semver（设置卡的「来源信息」读的就是这条声明）。
2. **语音回复（2026-10-25 实现；2026-10-26 真机复测：服务端接受但不投递，默认关）**：音频附件按 `voice_item` 语音气泡发出的整条管线都在（SILK 5/24kHz，wav/silk 进程内转码、其余走 ffmpeg，发送被拒仍降级为文件），但真机上 `ret=0` 后手机端收不到——插件外的探针 `ret=-2`（缺新鲜 token），插件路径 `ret=0` 也不投递，两次实测（2026-06、2026-10-26）一致，判定为服务端账号能力开关。`voiceOutbound` 默认 false；测试锚定这个默认。TTS（文字→语音合成）仍是另一回事，未做。

8. **部署方式（2026-10-26 补记）**：App 启动时会在 `<profile>/` 跑 `pnpm install`，按声明的 semver 从 npm 重装插件——手工 `node bin/install.mjs` 复制进去的源码会在下一次启动被覆盖（连新增的 `src/persona.js` 都消失）。所以「本地验证」用 install.mjs，「装好并长期生效」只能靠已发布版本 + profile 依赖声明 + 锁文件同步；npm 发布还需要人在终端完成一次网页 2FA。
9. **发版脚本钉住 profile 依赖（2026-10-26 已实现，随 0.9.7 发）**：第 9 步原来只 `install.mjs` 复制文件，App 下次启动的 `pnpm install` 又把旧版本装回来（0.9.5→0.9.6 又踩了一次）。现在脚本顺手把 profile 的 `dependencies` spec 从 `^旧` 改成 `^新`（文本级替换、保留缩进、`file:` 之类不动），再用 App 自带 pnpm 刷锁文件。
