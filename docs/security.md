# 安全策略

默认策略：

- 仅允许配置的稳定 Weixin sender ID；
- 查看项目和解释代码可用；
- 修改文件、运行命令、外网访问、提交推送必须由 DSH 权限层确认；
- 删除文件、读取密钥、发送 session/cookie/token 默认拒绝；
- 确认码一次性、短时有效并绑定 sender、conversation、动作摘要；
- 入站消息和工具调用写入审计日志；
- session 文件、密钥和二维码数据只存本机安全目录；
- 插件 transport 只监听本机，不暴露未经鉴权的公网端口；
- 入站附件（图片/文件/语音/视频）**先过白名单与去重，再从 CDN 下载**：未授权的发信人无法让本机
  对 CDN 发起请求；
- 入站文件名一律视为不可信数据，只取 basename 并加随机前缀后写盘，不参与路径拼接；
- 语音识别的桥进程是本机受信子进程，**只读本地文件、不联网**（模型下载由 `HF_HOME` 决定）；
  识别结果一律作为**用户原话**处理，不提升为工具授权。

## 出站附件（agent → 微信）

**允许的目录只有两个**：agent 会话的工作目录 `cwd`，以及插件状态目录 `~/.dsh/weixin`。
它们由 `allowedMediaDirs()`（`src/media/outbound.js`）构造，范围就在这里钉死。

路径检查是 `realpath` 之后再用 `path.relative` 判包含（不是字符串前缀，否则 `/wi/evil` 会被
当成在 `/wi` 里），并且：

- 包含检查在 `realpath` **之后**做，所以允许目录内部的符号链接指向 `/etc` 也会被拒；
- `..` 逃逸按 agent **写出来的原文**判定——先 `path.join` 会把 `..` 折叠掉，检查就看不见了；
- 相对路径依次在每个允许根下尝试，命中第一个真实存在的文件；全都落空就报「文件不存在」，
  **不会**退回到宿主进程的 cwd。

**放宽「引用识别」不改变这个边界。** 插件现在认得更多写法（markdown 链接、附件扩展名的相对路径、
`<...>` 包起来的带空格路径），但识别只决定「要不要尝试发这个文件」，决定「能不能读」的始终是上面
那条包含检查。认错一个相对路径的代价是 `resolveOutboundMedia` 返回 `not-found` 并如实告诉用户，
不会读到允许目录之外的东西。

两类扩展名的待遇不同，这是有意的：

- **图片等可内联渲染的**（`png/jpg/gif/webp/bmp`）只有 markdown **图片**语法 `![alt](p)` 才算引用。
  `[shot](a.png)` 是普通链接——agent 在**指路**，把它当成上传会把无关图片甚至源码树发去腾讯。
- **天然就是附件的**（`pdf/docx/xlsx/zip/mp3/mp4` 等，见 `ATTACHMENT_EXT`）链接语法也算，因为微信
  回复里没有任何东西会内联渲染一个 PDF，`[报告](报告.pdf)` 只可能是「把文件发我」。

## 威胁模型

微信文本不是可信的工具授权。账号被盗、转发消息、重复投递和模型误判都不能绕过 DSH 的工具权限层。任何来自微信的请求都必须经过 sender 白名单、消息去重、权限判定和必要的二次确认。

入站媒体按「先授权、后取件」排序：下载发生在 allowlist 与 dedupe 之后，因此拒绝路径上不会产生任何
出网请求。取回的字节按 `Content-Length` 与实际长度双重限流，解密失败不落盘，写盘用独占模式并做文件名
消毒，避免路径穿越、符号链接抢占与内存耗尽。

## 工具审计文件的边界（`toolAudit`）

审计是**本地观测**，不是授权机制：它记录「谁触发了哪个工具」，不改变工具权限层的判定。写审计失败
（目录不可写、磁盘满、参数无法序列化）只 warn，绝不影响一轮对话——观测工具不能反过来弄坏收发。

- 位置：`<状态目录>/audit/audit-YYYY-MM-DD.jsonl`，按天滚动，与消息流水（`<状态目录>/journal/`）分开；
- 内容：工具名、**截断到 500 字符**的参数、账号 / 会话 / 发送者、结果是否带错、耗时。**不记**工具输出
  内容（可能极大，且已在会话记录里）；
- 参数是模型产出的原文，可能包含密钥、令牌或内网路径。审计文件是本地文件，默认权限继承状态目录，
  但**不要把它直接贴进公开 issue 或日志**；需要分享时先手工脱敏；
- `/cancel` 打断的调用由桥补一行 `ok:false, aborted:true`（带已运行时长）。区别在于：`ok:false` 是
  「工具报了错」，`aborted:true` 是「没有人报结果，用户把它停了」——两者在事后追责里的含义完全不同；
- 白名单之外的发送者根本进不到 agent 轮次，因此不会产生审计行。

## 语音识别（ASR）的边界

ASR 把音频变成**文本**，这段文本在威胁模型里的位置与用户手打的文字**完全等价**：同样是不可信输入，
同样要过权限层。识别不增加新的信任。

- 转写结果只作为「用户说了什么」交给 Agent，插件自己的说明（`【语音转写】`、失败原因）与之分开标注，
  避免模型把插件的记账文字当成用户指令；
- 识别为空时**必须**如实说明并明确禁止编造内容——空结果不许被模型补全成一句看起来合理的指令；
- 未授权的发信人根本走不到下载与转码，自然不会触发任何 ASR 调用；
- 桥进程常驻，但每个请求只写它自己的 stdout；stdout 上任何**非 JSON** 的行都按诊断信息丢弃并记录，
  永远不会被当成一条转写结果；
- 桥崩溃、超时、拒绝服务都只降级为「附上音频文件」，不会挂起插件，也不会让消息丢失。
