# 扩展功能：日常可用的那些开关

这一页只写**怎么用**。每一项在 `docs/progress.md` 里都有实现与取舍记录，版本号标在标题后。

## 每条消息省下两次阻塞写（1.4.8）

```bash
npm run bench            # 假 iLink 压 100 条，报每条消息的挂钟/CPU/fsync 次数
npm run bench -- 400
```

这不是功能，是把「插件在你电脑上常驻」这件事当成本来算：

- `lastSeenAt`（卡片上的「安静了多久」）改成每账号一分钟最多写一次 —— 分钟级精度本来就够；
- 用量账本、当日预算、每人每日配额、生活状态、亲密度历史不再 `fsync`（`atomicWriteJson(..., { durable: false })`）；
- 提醒、订阅、记忆、人设、白名单、联系人、出站队列照旧持久写。

实测每条消息的阻塞写从 4 次降到 2 次。想自己复现，`npm run bench` 前后各跑一次即可。

## 通知桥：让脚本给你发微信（0.9.14）

长任务跑完、备份成功、cron 出错时，不用再等你主动来问：

```sh
TOKEN=$(node -p "require('$HOME/.dsh/weixin/notify.json').token")
curl -s -X POST http://127.0.0.1:47832/notify \
  -H "x-notify-token: $TOKEN" \
  -H 'content-type: application/json' \
  -d '{"text":"📦 构建完成"}'
```

- 在设置卡「配置项 → 通知桥」打开；默认关闭。
- 只绑 `127.0.0.1`，必须带 token。token 首次启动自动生成，存在 `<状态目录>/notify.json`（0600）；也可以用 `notifyToken` 自己指定。
- 纯文本也行：`curl … -d '构建完成'`。
- 每分钟最多 30 条，正文最多 4000 字（超出截断）；token 错了返回 401，发不出去返回 502。
- 推到最近说过话的那个会话；还没有任何会话时返回 502，不会静默吞掉。
- 它**不经过模型**，一条通知只花一条微信消息。

失败排查：日志里搜 `notify bridge`（端口占用）或 `notify send failed`（传输层）。

## 离开模式：出门时说一声，回来收一份汇总（0.9.14）

```text
/away 2h 开会        # 两小时后回来，备注「开会」
/away 20:30          # 到今晚 20:30
/away                # 只看还剩多久
/back                # 提前回来，立刻收汇总
```

- 离开期间消息照收，但**每个会话每 30 分钟最多自动回一句**「我现在不在，看到会回你～（大概 HH:mm 回来）」，不经过模型，不花 token。回复文案可用 `awayAutoReply` 覆盖。
- 其他消息记在 `<状态目录>/away.json`，最多 30 条；回来说 `/back`，或到点自动发一条汇总到最后一个找你的会话：几条、几个人、都说了什么。
- 命令始终可用（`/away`、`/back` 的拦截在命令处理之后），所以在离开模式里也能随时改时间或提前结束。
- `/away` 的时间写法与提醒一致：`10m`、`2h`、`20:30`、`2026-10-29 09:00`。

## 共享清单：群里的事有一处落脚（0.9.14）

```text
/todo                     # 看整份清单
/todo add 周末买牛奶       # 加一条（直接写「/todo 周末买牛奶」也行）
/todo done 2              # 第 2 条做完了
/todo rm 2                # 删掉第 2 条
```

- 按**机器人账号**存，不按会话：同一个机器人的群聊和私聊看到的是同一份清单 —— 这才叫共享。
- 每条记下是谁在哪个会话加的、什么时候完成；序号就是当前显示的顺序。
- 上限 100 条；满了会明确拒绝，并提示先 done / rm，而不是悄悄挤掉最旧的。
- 状态在 `<状态目录>/lists.json`，原子写；群里几个人同时加也不会写坏。

## 稍后读：链接不再被刷走（0.9.14）

```text
/later https://example.com/post   # 存链接，插件取回标题
/later 读那篇讲 RSC 的文章        # 不是链接也行，原样存一条
/later                            # 看清单（未读/总数）
/later done 2                     # 第 2 条读完了
/later rm 2                       # 删掉第 2 条
```

- 按账号存，状态在 `<状态目录>/reading.json`，上限 50 条。
- 标题取不到就退回域名（`news.example.org`），不会因为网络问题存不进去；非链接文本不会触发任何网络请求。
- 同一条未读链接只存一次；标记读完后再存同一个 URL 会作为新的一条。

## 要一个文件：`/send`（0.9.14）

```text
/send out/report.pdf          # 相对工作目录
/send /Users/me/notes/todo.md # 绝对路径也行，但必须在允许的目录里
```

- 只发真实存在的普通文件，且必须落在**工作目录、状态目录、`mediaDirs`** 之内（与自动附件同一套 `resolveAllowedPath` 守卫，`..` 与符号链接逃逸都拒绝）。
- 受 `maxMediaBytes` 限制（默认 100 MB），超了直接说明，不会偷偷截断。
- 发送失败时文件保留，回复里说明失败，不会假装已发。

## 加密备份：把状态带走（0.9.14）

`npm run backup create` 是目录对目录的快速回滚，**不设防**——里面就是明文 token 和聊天原文。要跨机器或放网盘，用密封备份：

```bash
export DSH_WEIXIN_BACKUP_PASSPHRASE='一句只有你知道的话'
node bin/backup.mjs seal ~/Desktop/weixin-state.enc
# 另一台机器 / 恢复时
node bin/backup.mjs open ~/Desktop/weixin-state.enc
```

- AES-256-GCM + scrypt（随机 salt/iv），密文带认证标签：口令错或文件被改会直接拒绝，不会还原出半套状态。
- 只封 `config.json`、`memory/`、`journal/` 等真实状态；跳过 `backups/`、`instance.lock`、`node_modules`。
- 恢复前会检查 DSH 是否在跑（在跑就拒绝，`--yes` 可强来），写入走临时文件 + rename。
- 口令不写进任何文件，也不进命令行历史（走环境变量）。

## 省钱路由：三种花销分开定价（0.9.14）

| 配置 | 谁在用 | 留空时 |
| --- | --- | --- |
| `chatProvider` / `chatModel` | 主对话 | 会话默认 |
| `sideProvider` / `sideModel` | `/summary`、`/subscribe` 到点 | 记忆模型 → 会话 |
| `proactiveProvider` / `proactiveModel` | 主动开口 | side → 记忆 → 会话 |
| `reportProvider` / `reportModel` | 日报、记忆核对 | side → 记忆 → 会话 |

主动开口只有一句，放最便宜的模型；日报要读流水再压缩，单独给一个。两者都必须成对填写，只填一半不生效（回落到下一层），避免把自己路由到一个没有模型名的线路。

## 文档理解：发进来的文件能直接问（0.9.14 起，PDF 从 0.9.15 起）

把 `.docx` / `.txt` / `.md` / `.csv` / `.json` 发到微信里，插件会在下载后把**正文**拼进这一回合的提示，你可以直接问「第三条写了什么」，不用打开文件。

- `documentExtract`（默认开）控制是否抽取；`documentTextChars`（默认 4000）是每个文档的上限，超出会截断并注明。
- `.docx` 是零依赖解析（zip + `word/document.xml` + 去标签）。
- `.pdf` 走**可选依赖** `pdfjs-dist`：装了就把正文抽出来（按页取文字，保留换行），没装就只给路径并在日志里说明原因——不假装支持，也不把几十 MB 的解析器塞进默认安装。要启用：在插件所在环境执行 `npm i pdfjs-dist`（DSH profile 里则是 `pnpm add pdfjs-dist`）。只取文字，不需要 canvas。
- 抽出的正文和用户消息一样按不可信内容转义，不会把文档里的标签变成指令。

## 引用回复：被引用的那句话也进上下文（0.9.15）

别人引用一条消息再回你时，微信不会把原消息重发一遍，只在 item 上挂一个 `refermsg`。插件现在会把里面的发送者、标题和正文读出来，拼成提示开头的：

```
【引用 小王】
下午三点开会
```

- 三种常见形状都认：`item.refermsg`、`item.appmsg.refermsg`（引用卡片）、`item.quote.refermsg`。
- 只引用、不配文的消息也会走模型（以前 text 为空会被当成「没看懂」）；外层是插件不认识的 item 类型时，引用内容仍然能到达模型。
- 引用文本按不可信内容处理：先 `redactSecrets` 脱敏、截断到 500 字，再由 `neutralizeTags` 转义。

## 重要日子的当天提醒（0.9.15）

记忆里的「重要日期」（生日、纪念日，`/remember` 或设置卡写入）和带日期的待办，到了当天会收到一条短消息：

```
📅 今天是重要日子
- 生日（第 36 年）
- 交房租
```

- 每天 `dateReminderWhen`（默认 `09:00`，本地时区）之后检查一次，当天只发一条；没命中就不发，也不标记 —— 当天晚些时候补记的日期仍来得及。
- 不跑模型、不花 token、不写消息流水。
- 已完成的待办（`done`）和没写日期的待办不会触发；没有日期的「重要日期」条目本来就不会被记忆接受。
- 关掉：`dateReminderEnabled: false`，或设置卡「汇报」组里的开关。

## 识别图片文字：OCR 桥（0.9.15）

插件不内置识别引擎，只规定一个最小约定：**一个可执行文件，唯一参数是图片路径，stdout 是文字**。配置 `ocrEnabled: true` + `ocrCommand` 后，每张入站图片都会被它读一遍，结果作为 `<weixin_ocr>` 块拼进这一回合的提示。

接 tesseract 的 wrapper（存成 `/usr/local/bin/ocr-img` 并 `chmod +x`）：

```bash
#!/bin/sh
exec tesseract "$1" stdout -l chi_sim+eng 2>/dev/null
```

- 超时 `ocrTimeoutMs`（默认 20000）到点直接 `SIGKILL`，按「没有文字」处理；退出码非 0、输出为空同样只降级，不让回合失败。
- 每张图最多保留 `ocrMaxChars`（默认 2000）字。
- 不配置就完全不走这条路：图片仍按原来的方式保存、把路径交给模型。
- 识别结果是不可信文本，和文档正文一样先 `neutralizeTags` 再进提示。

## 出站 webhook：把发生的事推给你自己的系统（0.9.15）

通知桥是入站（外面推一条给微信），webhook 是出站（插件把事件推给 n8n、面板或日志服务）。配置 `webhookUrl` 即开启：

```
POST https://your-host/hook
content-type: application/json
x-weixin-signature: sha256=<hex>        # 配置了 webhookSecret 才有

{"event":"message.received","at":"2026-10-31T02:00:00.000Z","accountId":"…","conversationId":"…","text":"…"}
{"event":"reply.settled","at":"…","accountId":"…","conversationId":"…","sent":true}
```

- 两个事件：`message.received`（通过闸门、即将进模型）与 `reply.settled`（发出成功，或因失败进了 outbox 时 `sent:false` + `queued`）。
- 签名对**原始 body** 做 HMAC-SHA256，密钥是 `webhookSecret`；校验示例（Node）：
  ```js
  const expected = 'sha256=' + crypto.createHmac('sha256', secret).update(rawBody).digest('hex')
  crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(req.headers['x-weixin-signature']))
  ```
- 超时 `webhookTimeoutMs`（默认 5000）；非 2xx、网络错误、超时都只写日志，不影响回复。
- 只支持 http(s)；URL 不合法时启动日志会说明并停用，不会悄悄重试。

## 后台预算：给不面向用户的调用设个上限（0.9.15）

记忆折叠、日报、记忆核对、订阅到点、主动开口都会真的调模型，但它们不由某条用户消息触发——出问题时没人立刻发现。`backgroundDailyLimit` 给这些调用一个**按天**的总量：

- 默认 `0` = 不限；配成正数后，当天后台调用达到上限就不再发起，日志写 `background model call skipped: background budget N/N used today`。
- 跨天自动归零；计数在 `<状态目录>/budget.json`。
- **主对话永远不受影响**：用户说话不受预算限制，闸门只装在 `AgentBridge.summarize()` 这一条后台入口上。
- 被挡下的调用不计数、不 attach、不计费。

## 提醒时间说人话（0.9.17）

`/remind` 的时间除了 `10m` / `18:30` / `2026-10-20 09:00`，还认这些口语写法：

| 写法 | 含义 |
| --- | --- |
| `明天 9:00` / `明天9点` | 明天 09:00 |
| `后天下午3点半` | 后天 15:30 |
| `今晚8点` | 今天 20:00（已过则报错，不悄悄改到明天） |
| `下周一 10点` | 下一周的周一 10:00（`周一` 才指本周） |
| `3小时后` / `半小时后` | 相对现在 |
| `9点` | 今天 09:00，已过则明天 09:00（与 `09:00` 同一规则） |

只给日期不给钟点（`明天下午`）会明确要求补时间，不替用户猜。时间本身可以带空格，命令按「第一个能解析的时间前缀」切分，剩下的都是提醒内容。

## `/diag`：它为什么没动静（0.9.17）

「怎么不回我」多数时候不是崩了，而是某个闸门关着。`/diag` 把答案压成一条消息，**不调模型、不花 token**：

```
自检 · v0.9.17 · 宿主 0.2.1-rc.5（已测）
账号：b1b2…@im.bot
模式：女友（陪聊）
开关：主动开口 开 · 记忆 开 · 群聊 关 · 免打扰 开 · 文档抽取 开
待发：提醒 2 条 · 订阅 1 条
主动开口：今天 1/3 条 · 上次 2026/10/31 09:12:03 · 连发未回 0 次
数据：今天流水 12 条 · 会话记忆 4 个 · 白名单 1 人
免打扰：当前不在静默时段
```

看三行就够：**连接**（收不收得到）、**开关**（主动开口/记忆/群聊是否被关）、**免打扰**（现在是不是静默）。主动开口不触发时，先看额度是不是用完、`连发未回` 是否触发了退避。

## `/outbox`：没发出去的那句话去哪了（0.9.17）

出站失败不是消失：`sendChunked` 会把失败的那条（含后续分块）写进本地队列，后台每 30 秒按退避重试，重启也不丢。但以前只能从设置卡里看见它，聊天里没有入口。

```
/outbox
待重发 1 条：
1. m3k2-9f1a · 5 分钟前 · 尝试 2 次 · 上次失败：fetch failed
   刚下班，路上风有点凉…

/outbox retry 立即重试；/outbox drop <id> 丢弃一条。
```

- `/outbox retry` 调 `flush({force:true})`，忽略退避立刻再试，回报发出/失败/剩余条数。
- `/outbox drop <id>` 丢弃一条（比如内容已经过时）。
- 队列按账号隔离，最多保留 200 条；`/diag` 里的「今天流水」不会因为重发而重复计数。

## 群里被叫到才回：把称呼写对（0.9.17）

群聊默认 `groupChatEnabled: false`；打开后默认只答**被叫到**的时候。iLink 不提供 @ 列表，也不告诉插件机器人在群里的昵称，所以匹配只能靠名字：

```jsonc
{
  "groupChatEnabled": true,
  "groupReplyWhen": "mention",
  "groupBotNames": "小助手, 阿伟"   // 大家实际 @ 的名字，逗号分隔
}
```

- 认 `@小助手`、`＠小助手`（全角）、`@小助手` 后面跟微信的 U+2005 细空格、英文大小写；
- 名字出现在首行开头或空白之后才算，正文深处的同名不算（宁漏勿扰）；
- `groupReplyWhen: "all"` 仍然逐条都答，适合工作群里的值班机器人。

## 重复提醒：每天 / 工作日 / 每周X（0.9.17）

```text
/remind 每天 9:00 吃药
/remind 工作日 8:30 打卡
/remind 每周一 10点 复盘
```

- 触发后**不会消失**：下一次的钟点从「这一次本该响的时刻」往后推，所以免打扰把某次推迟到夜里，也不会把第二天的挤掉；
- 周末的「工作日」会顺延到周一；`每周一` 永远指下一周的周一；
- `/remindlist` 会标出 `（每天 09:00）` 这样的重复说明，`/remindcancel <编号>` 一次性取消全部后续；
- 仍然零模型消耗：到点发固定文字，不调 agent。

## 临时静默：`/quiet 2h`（0.9.18）

固定的免打扰时段（`quietHoursStart/End`）管的是「每天这个点都别吵」；开会、看电影、开车这种两小时的状态，用它得改配置再改回来。`/quiet` 把「到某个时刻为止」存成一个账号级状态：

```text
/quiet 30m      # 静默半小时
/quiet 2h       # 静默两小时（最长 24 小时）
/quiet          # 看还剩多久
/quiet off      # 立刻恢复
```

静默期间：**不主动开口**（连判断都不做，不花 token）、**离开模式不自动回复**（未读照记）、**提醒与 /subscribe 顺延到结束**。你发来的消息照常回 —— 人都在打字了，再装死就是另一回事。到点自动恢复，不用记得关。

## 提醒的「等会儿」：`/snooze` 与 `/remind skip`（0.9.18）

提醒到了，但人正忙：不用取消再重排，直接推。

```text
/snooze 10m      # 最近一条待发提醒往后推 10 分钟
/snooze 1h
/remind skip     # 重复提醒（每天/工作日/每周X）跳过下一次，从再下一次继续
```

- `/snooze` 只动**一条**（最早的那条），重复提醒的周期也一起顺延，不会出现「刚推后又被原周期拉回去」；
- `/remind skip` 只对重复提醒有效；一次性提醒要取消请用 `/remindcancel`；
- 两者都不调模型、不发消息，只改磁盘上的排期并重新上定时器。

## `/usage`：今天花了什么（0.9.18）

不调模型的一条账单，数字全部来自已有状态文件（`budget.json`、`proactive-<account>.json`、`outbox.json`、`reminders.json`、当天的 `journal-*.jsonl`）：

```text
用量 · 今天
后台调用：7/20 次
主动开口：2/3 条 · 上次 15:42 · 连发未回 1 次（退避中）
待重发：1 条
待发提醒：4 条 · 订阅：2 条
今天流水：12 条 · 正文粗估约 640 token
```

**粗估就是粗估**：只把当天出入站正文的字符按中英折算成 token，不含系统提示词、工具结果与历史上下文 —— 它回答的是「今天大概动了多少次、发了多少字」，不是账单级的精确值。后台预算用完时，最后会多一行说明哪些能力停到明天零点。

## 习惯打卡：连续天数看得见（0.9.18）

提醒负责喊你，但喊完就没了 —— 做没做、连着做了几天、这周漏了几次，得有个地方记。

```text
/habit add 早起      # 开始追踪
/habit done 早起     # 今天打卡（也可 /habit done 1）
/habit               # 看所有习惯
/habit rm 早起
```

输出形如：

```text
习惯 · 今天 1/2
1. ✅ 早起 · 连续 2 天 · 本周 2/7
2. ⬜ 跑步 · 连续 0 天 · 本周 0/7
```

- **连续天数**按本地日期算：今天还没打卡不算断（从昨天起算），只有昨天也漏了才归零；
- 状态是 `habits.json`（按账号、原子写），每个账号最多 20 个习惯；不调模型；
- 打过的卡会以一行「习惯打卡 1/2：早起✅（连续 2 天）」进当晚的日报（如果开了日报）。

## 媒体归档：找回上周那张图（0.9.18）

微信发来的图片、文件、语音都落在 `~/.dsh/weixin/media/inbound/`，文件名是一串 UUID，时间一长就认不出。

```text
/media              # 最近 8 件，按时间倒序
/media resend 3     # 把第 3 件重新发回当前会话
```

输出形如：

```text
最近的媒体（3 件）：
1. 今天 14:02 · image · 812.3 KB · 3f9c1a2b-……png
2. 昨天 20:11 · document · 2.0 MB · 7ad02e4c-……pdf
3. 10-28 09:12 · voice · 24.1 KB · 0b5f77ac-……silk
```

- 只列**文件**（目录跳过），按修改时间倒序，最多 20 件；
- `resend` 的路径判断是 realpath 后必须仍在归档目录内 —— 归档能看，但不会因此变成任意文件发送的后门；重发走的是与模型回复附件同一条 `sendMedia` 管线；
- 发送失败时文件保留，回复里给出原因与路径。

## 群里每人每天聊多少：`senderDailyLimit`（0.9.18）

`senderRatePerMinute` 管的是「一分钟内别刷屏」，但一个人一天发 300 条它一条也拦不住；`backgroundDailyLimit` 管的是整个账号的后台预算，一个人就能把它用光。

`senderDailyLimit` 是第三种：**每个发送者、每个账号、每天**最多被回复几次。

```jsonc
{ "senderDailyLimit": 30 }   // 0 = 不限（默认）
```

- 按**人**算，不按会话：同一个人在私聊和群里发的，共用同一份额度；
- 按**账号**分开：同一个人的两个微信号各有各的额度；
- 到量后当天不再回应，**只回一次**「今天跟你聊得够多啦」并写审计（`weixin/daily-limit`），5 分钟内不重复提示；
- 跨天自动归零，用本地日期，不是 UTC；
- 检查发生在白名单之后、链接抓取与媒体下载之前 —— 被拒绝的人不会让这台机器再去请求任何外部地址。

## 重要日子提前提醒：`dateReminderLeadDays`（0.9.18）

```jsonc
{ "dateReminderEnabled": true, "dateReminderWhen": "09:00", "dateReminderLeadDays": 3 }
```

- `0`（默认）只在当天说；`3` 会在生日/纪念日/待办日期的前三天先说一句：
  当天那段是 `📅 今天是重要日子`，提前那段是 `🗓 快到了`（`- 明天：交房租`、`- 3 天后：生日（第 36 年）`）。
- 「下一次」永远指向未来：已经过去的那个月日会算到明年，不会因为窗口设了 3 天就把昨天的事又说一遍。
- 已完成（`done: true`）的待办不提醒；窗口最大 30 天；一天只发一条，格式固定，不调模型。

## `/digest`：不等 21:00 的日报（0.9.19）

定时日报每天 21:00 由侧会话生成；`/digest` 用**同一个** `composeDigest` 现算一次：数字来自当天流水、事件来自长期记忆、习惯来自打卡记录。

```text
/digest
```

- 它不在聊天里再发一条 —— 命令的回复本身就是日报，所以连问两次不会在会话里堆两条报告；
- 今天一条流水都没有时直接说「没什么可写的」，不硬凑；
- 走 `reportProvider/reportModel` 那条便宜路由（留空则回落到后台任务路由）；
- 不写 journal、不动 21:00 的定时器。

## 归档清理：`/media clean` 与 `mediaMaxBytes`（0.9.19）

`media/inbound` 只按时间清理（`retentionMediaDays`，默认 30 天），朋友连发一百张图时仍然会涨。

```text
/media clean        # 立刻按 retentionMediaDays 清一次
/media clean 7      # 只清 7 天前的
```

设置卡里还有 `mediaMaxBytes`（0 = 不限）：超过上限就从**最旧**的文件开始删，直到落回上限；上限以内一个都不动（最新的那批不会因为一次清理就消失）。两者都会在回复里报告删了几件、多少字节，以及归档里还剩多少。

## 统计页签看得见什么、看不见什么（0.10.0）

「统计」页签现在多了三块自绘的东西（纯内联 SVG，零依赖）：

- **每会话迷你折线**：最近 14 天每天这个会话有多少条消息，缺失的天补 0。
- **提示词构成条**：最近一个回合里，人设 / 语气 / 生活状态 / 群成员名片 / 记忆 / 往事检索 / 预演约定 / 这条消息与附件各占多少**字符**。运行时记录（`recordPromptComposition`），所以它描述的是「刚才那一次」而不是「配置上大概会怎样」。重启后没有记录，卡片显示「还没有记录到一个回合」。
- **健康度环**：25×4 —— 连接、投递（待重发条数 0/1–3/更多）、预算（未设上限或用掉 <80% / <100% / 用满）、留存（三个保留天数都设了没有）。环下面逐行写着口径。**这是运维口径，不是模型评分。**

数据边界（这张卡片上写得明明白白）：

| 想要的东西 | 能不能给 | 为什么 |
| --- | --- | --- |
| 收发条数、按天/小时分布、会话序列 | 精确 | 本机消息流水现算 |
| 提示词各段占比 | 精确到字符 | 运行时记录实际拼进去的长度 |
| token 用量 | 拿不到 | `dsh-agent` 事件里没有 `usage`；`dsh-llm` 的 usage 只在流式 chunk 里，不经过插件 |
| 缓存命中率 96% 那种数字 | 拿不到 | 同上，属于网关记账，不在插件链路上 |
| 账户余额 / 积分 / 预计用完时间 | 拿不到 | 供应商账户 API 与宿主登录态都不向插件开放 |

所以卡片上**故意没有** token 与缓存那两栏；底部一行写着「宿主不把这两样交给插件，写出来的任何数字都只能是猜的」。宁可少画两个数字，也不让人拿它当账单去对。

## 消息流水：从日志列表改成聊天时间线（0.9.21）

原来的「消息流水」页签是一行一条的纯文字：`时间 ↑/↓ 账号 发送者: 文本`。能查，但读起来不像聊天。

现在它是按本地日期分组的聊天时间线：

- **今天 / 昨天 / 月-日** 的分隔线，气泡靠左（收到 ↓）或靠右（发出 ↑），圆角在朝向发送者的那一角收小；
- 气泡下面是 11px 的小字：时间、账号、发送者；
- 顶部三个筛选：**全部 / ↓ 收到 / ↑ 发出**；窗口从 50 条提到 200 条，列表在卡片内滚动（`maxHeight: 460`），长消息 `pre-wrap` 换行、`overflow-wrap: anywhere` 不撑破；
- 空态是一句「还没有记录到的消息。」，不再是空白；
- 「导出记录」「刷新」两个按钮位置不变。

配色全部取宿主主题 token：收到的气泡用 `surfaceSunken` + `border`，发出的用 `primaryFill` + `onPrimary`，所以明暗主题都跟着走，没有写死颜色。

实现上只有一处数据变化：`journal` 远程调用从 `limit: 50` 改成 200（返回的仍是 `{at, dir, accountId, senderId, text}` 数组，没有新字段、没有新状态）。测试是源码形状断言（`test/client-remote.test.js`），因为卡片是宿主渲染的，跑不了 DOM。

## 卡片界面：颜色、动效、进度（0.9.21）

设置卡此前只有一块「能用」的界面：九页签是九个纯文字按钮，状态只有一个点，进度只有语音模型下载那一条。这次补的是一层**共用的设计层**，而不是逐处调样式：

- **一块自带的样式表**（`STYLE_ID = "dsh-weixin-card-styles"`）：卡片是懒加载 chunk，宿主不提供 CSS 通道，所以 chunk 首次渲染时注入一次 `<style>`，定义 `wx-fade-in / wx-pulse / wx-spin / wx-sweep` 四组 keyframes 与 `.weixin-tab`（hover/focus-visible）、`.weixin-row`（hover）、`.weixin-card-enter`（切页签入场）、`.weixin-indeterminate`（不确定进度扫光）。`typeof document === "undefined"` 时直接跳过 —— 测试用的 stub 环境没有 DOM，不能因为「美化」把测试弄崩。末尾 `@media (prefers-reduced-motion: reduce)` 关掉所有动画。
- **一组原语**：`Spinner`（旋转弧，可指定尺寸/颜色）、`PulseDot`（呼吸点，ok/warn/danger/idle 四色）、`Progress`（有数字走宽度过渡、没数字走扫光）、`Badge`（五档色调的小胶囊）、`StatTile`（数字卡）、`EmptyState`（空态）、`TabIcon`（九个页签各一枚 15px 内联 SVG）。
- **九页签加了图标**，选中态是「浅底 + 品牌色下划线 + 加粗」，hover 有过渡；内容区按页签 id 重新挂载，所以切页签会重放一次 0.22s 的入场动画。
- **登录页**：状态行从「一个点 + 一行字」变成按状态着色的横幅（成功/待处理/失败各有底色与描边），账号 id 与「需要处理」改成 `Badge`。
- **会话页**：每行前是 `PulseDot`（使用中为绿色呼吸），「使用中」变成 `Badge`，行有 hover 过渡。
- **提醒页**：每条提醒是一张小卡，左侧点在一小时内变琥珀色，第二行是「时间 · N 小时后」，空列表用 `EmptyState`。**这里刻意不画进度条** —— 提醒只有到期时刻、没有开始时刻，画百分比就是编数据。
- **关于页**：「版本」一行变成三张 `StatTile`（已安装 / 包名 / 更新状态），检查更新时按钮前出现 `Spinner`。
- **修掉一个真 bug**：页签下划线此前用 `C.stateOk`，这个 token 不存在（主题里叫 `success`），所以选中下划线一直是透明的；统一改成 `C.brand`。

所有颜色都来自主题 token，明暗主题自动跟随；没有引入任何依赖，也没有写死颜色值（唯一的例外是二维码白底，那是扫码可靠性要求）。

## `/undo`：记错了能撤回来（1.2.0）

`/remember` 写进去的东西以前只能手动删：`/forget` 要编号、要关键词，改口还得写成「旧 → 新」。一句话记错，用户当晚就得跟机器人较劲。

现在每次长期记忆改动都留一条**撤销记录**，和事实存在同一个文件里（`global-<account>.json` 的 `history`，最多 20 步）。`/undo` 撤最近一步，`/undo 3` 连撤三步（上限 5）：

| 当时做了什么 | `/undo` 之后 |
| --- | --- |
| `/remember 我对花生过敏` | 那条事实消失 |
| `/remember 我住北京 → 我搬到杭州了` | 「我搬到杭州了」消失，「我住北京」回来 |
| `/forget 1` | 被删的那条回来 |
| 记忆整理自动改口 | 同「改口」 |

**只认最近 30 分钟**。这条限制不是抠门：一个「撤销」按钮如果隔一周还生效，某天手滑打出一个 `/undo` 就会删掉早被当成常识的事。更早的改动请用 `/forget 编号` 手动处理——那一步会把你删的内容原样告诉你。

`/memory` 每行后面现在也带括号：**最后一次确认是多久以前、从哪来的**。

```text
长期记忆（括号里是最后一次确认的时间与来源）：
1. 我对花生过敏（12 天前 · 来自/remember）
2. 我住在杭州（今天记的 · 来自记忆整理）
3. 我妈生日 5 月 20（3 天前 · 来自撤销恢复）
```

「多久以前」按最后确认时间算，不是最早写入时间：一条被改口纠正过的事实，日期会往前跳——这件事被重新确认过。老版本写下的事实没有来源，会显示「时间未知」，不会被编一个出来。

实现上，`addGlobalFact` 与 `removeGlobalFact` 各追加一条 `{kind: 'add'|'replace'|'remove', text, at, by, restore}`；`undoLastMemoryChange(stateRoot, accountId, {within, now})` 负责反向施加并吞掉那条记录。撤不动（例如那条事实已经被别的方式删了）时它会明确回「没有可撤销的记忆改动」，而不是假装成功。


## 记忆冲突：同一件事说了两个版本，先问一句（1.2.0）

模型抽出来的事实如果有 `supersedes`，`addGlobalFact` 会原地替换。但用户亲口 `/remember` 的时候没人管这件事：

```text
你：/remember 我住在杭州
机器人：已记住：我住在杭州
（一周后）
你：/remember 我住在上海
机器人：我记得你说过「我住在杭州」。现在要改成「我住在上海」吗？回「是」我就换掉，回「不用」我就保留原来的。
你：/是
机器人：好，那就改成「我住在上海」。
```

以前这两条会并排躺着，注入上下文时模型拿到两份互相打架的说法，只能瞎选一份——而且选哪份都算「记得」。

判断「同一件事」用的是很笨但足够可靠的办法：把两句话切成词（中文按两字一组，英文数字整词），算编辑距离。**只差 1–2 个词**、且两边词数相差不超过一半，才认为是同一个槽位：`我住在杭州` / `我住在上海` 差一个词，问；`我住在杭州` / `我对花生过敏` 差太多，不问。四个词以下的句子根本不比——`早安` 和 `晚安` 看起来像，问出来只会烦人。

几条刻意的保守：

- **只问一次**。问题存在内存里，10 分钟没回答就作废；回答「不用」或说别的事都会让问题消失。它永远不会在文件里躺着，一周后突然冒出来。
- **只在 `/remember` 上问**。模型后台整理记忆时走的是 `supersedes`，它自己知道哪条替换哪条，不需要问。
- **答案要短**。`/是`、`/不用`、`/对`、`/别改` 这些才算回答；`/是的明天帮我订个外卖` 是普通消息，照常进会话。

实现上，`src/message/memory-conflict.js` 提供 `findMemoryConflict`（找最像的那条）、`MemoryConflictQueue`（进程内的待答问题，带 TTL）和 `parseConflictAnswer`（只认短句）。路由上有一处要小心：`/是` 走的是命令表的**答案分支**，它排在普通命令之前，否则 `/是` 会被 `/use` 的前缀规则截走，回一份会话列表。

## 记忆过期自检：告诉它「这条已经不对了」（1.2.0）

长期记忆只增不减。半年后里面躺着「我在做 A 项目」「我住在杭州」，人已经在做 B、也搬了家——机器人会一本正经地拿旧事实推理，而用户根本不知道哪些话已经过时了，只会觉得它「记性变差」。

`/memory stale` 把「很久没被确认过」的那几条列出来：

```text
超过 90 天没确认过的记忆，共 2 条：
2. 我在做 A 项目（210 天没提起了）
5. 我住在杭州（120 天没提起了）

看完之后可以这样处理：用 /remember 重新确认一遍（会刷新时间），或者 /forget <编号> 删掉。
长期记忆一共 7 条，都在 /memory 里。
```

口径只有一条：**最后一次被写入或改口的时间**。改口会刷新它，因为那次对话本身就是一次重新确认——所以纠正过的事实不会来烦你。天数由 `memoryStaleDays` 控制（默认 90 天，最小 7 天）。

日报里也会带一行，但只在真有陈旧记忆时：

```text
有 2 条记忆超过 90 天没提过（我在做 A 项目、我住在杭州），发 /memory stale 可以一起核对
```

刻意不做的事：

- **不自动删，也不自动改**。过期只是「可能不对」，不是「一定不对」——删记忆的权限只在你手上（`/forget`、`/undo`）。
- **不天天提**。日报每天以待办结尾，很快就会被忽略；只有陈旧条目存在时才出现这一行。
- **老事实不算过期**。没有时间戳的条目（早期版本写的）归到「不知道是什么时候写的」，单独一句，不混进过期列表吓人。

## `/import`：换机器、重装、从备份回来（1.2.0）

`/memory export` 早就能把记忆带走，但带回来只能靠手抄。现在反过来也行：

```text
你：/import <把 /memory export 存下来的那份 Markdown 整段粘进来>
机器人：从粘贴的内容里读到：
       - 长期记忆 3 条：我对花生过敏；我住在杭州；我妈生日 5 月 20
       - 事件与待办 1 条：体检
       - 档案 2 项：call、dates
       - 人物小传 213 字
       （其中 1 条已经记过了，会跳过）
       
       确认的话回「是」，我就写进去；回「不用」就什么都不改。
你：/是
机器人：导入完成：3 条长期记忆、1 条事件与待办、档案 2 项、人物小传。
       （/memory 看现状，记错了 /undo 撤销最近一条）
```

四条规矩：

- **先给预览，回「是」才写**。预览里说清楚读到了什么、哪些会跳过、长期记忆放不下时还有几条导不进来——不会先写进去再告诉你。
- **只增不删**。已有的长期记忆和待办一条都不动，只补新的；导入的事实来源记成 `/import`，`/memory` 能看出来是哪来的。
- **认不出来就跳过**。只认导出文件里的那几个章节（人物小传、档案、事件与待办、长期记忆），别的章节一律忽略，跳过的行数会报出来。宁可少导一条，也不把「会话记忆」里那段散文当成长期事实。
- **预览十分钟有效**。超过十分钟才回「是」会拒绝并要求重新 `/import`，免得你离开一趟回来，一句「是」把早忘掉的旧备份写进现在的记忆。

`/import` 与冲突确认共用同一个「回答」入口：`/是` 先看有没有待确认的导入，再看有没有待确认的记忆冲突，都没有就照常当聊天。

## 提醒的两种「顺延」写法（1.2.0）

**说星期几就够了。** `/remind 周五 交周报` 以前会被拒绝（「还需要一个钟点」），因为一天里哪个时刻猜不出来——但对星期几来说这不是问题，早上 9 点就是默认值：

```text
/remind 周五 交周报          → 2026-11-06 09:00
/remind 下周三 10点 开会      → 2026-11-11 10:00
/remind 这个周六 下午3点半 打球 → 2026-11-07 15:30
```

`下周一` / `下个周一` 都算下周（不是本周一）；`周一` 指本周，如果本周一已经过去（比如今天周三），就顺到下周一——「周一」说出口时人想的是「下一个周一」。`周天` 在周日当天说，也是指下一个周日。

**按序号往后推。** 以前只能 `/snooze`，而且只推最早那一条。现在 `/remindlist` 带编号：

```text
待发的提醒（/remindlist <序号> <时长> 可以把某一条往后推，例如 /remindlist 2 1h）：
1. 11/1 18:00 · 喝水（编号 r3）
2. 11/1 19:00（每天 19:00） · 吃药（编号 r4）

> /remindlist 2 1h
已把第 2 条推后 60 分钟：吃药（11/1 20:00）
```

编号按触发时间排，和列表里看到的一致；重复提醒被推后时，下一次的基准也跟着挪，不会在原来那个点在背后再响一次。

## `/keyword stats`：哪条规则在干活（1.2.0）

群关键词规则是静默的模板回复——写错了正则，表现和「没人发过」一模一样。`/keyword stats` 把规则和命中次数摊开：

```text
你：/keyword stats
机器人：群关键词规则 2 条（命中次数是插件启动以来的累计）：
       1. ^打卡$ → 打卡成功
          命中 12 次 · 最近一次 今天 09:12
       2. ^没人用$ → x
          命中 0 次 · 还没响过
       （这些规则一次都没命中过：检查正则大小写、^$ 锚点，以及是不是只在群里生效）
```

- **配置里有、从未命中的规则也会列出来**——「没出现在统计里」不能被误读成「这条规则不存在」。
- **「因为冷却被吞」单独计数**：命中 30 次却有 25 次被 60 秒冷却吃掉，说明规则写得比大家发的还宽，冷却在替它兜底。
- 计数是**进程内累计**，重启清零。它回答的是「这条规则最近有没有在响应」，不是账本——所以没有落盘，也没有「重置」这种需要解释的操作。

## `/diag export`：问问题之前，先把它脱敏（1.2.0）

`/diag` 的回答在聊天里，想拿去问人就得截图或者手抄。`/diag export` 把同一件事写成一份可以转发的 Markdown：

```
你：/diag export
机器人：已导出体检包（7 节，id 已换成短哈希、地址与凭据已抹掉）：
       /Users/you/.dsh/weixin/diag/diag-2026-11-01T03-12-09-118Z.md
       转发出去之前建议自己扫一眼。
```

七节：版本、账号、模式、开关、计数、最近报错、自检结论。

- **账号与发送者只出现短哈希**：`id-3f9a1c` 这种形状，能看出「是不是同一个人」，看不出是谁。白名单只给数量，不给内容。
- **每一行都先过一遍脱敏**再拼：URL、邮箱、手机号、24 位以上的长串、`token=` / `secret=` / `password=` / `key=` / `authorization=` 后面的值统统换成 `[已隐藏]`。这是写死在拼接处的，不是「记得脱敏就脱敏」。
- **只带失败的那几条审计**，最多 8 条。成功的记录对「为什么出问题」没有解释力，只会让文件变长。
- 自检结论是几句白话：连接没就绪、宿主版本不在测试列表、白名单为空、主动开口关着、记忆关着、最近有失败记录——有问题才会写。

文件写在状态目录的 `diag/` 下，不会自动上传到任何地方；发不发由你决定。

## `/config`：改完到底生效了吗（1.2.0）

设置卡保存就写进 `config.json`，但「写进去了」和「什么时候算数」是两件事：

```
你：/config
机器人：配置一共 107 项：101 项保存即生效，6 项要重启。
       · 保存即生效（下一条消息就按新值走）：enabled、accountId、cwd、allowedSenders 等 101 项
       · 重启 DSH 后才生效：sendIntervalMs、voiceOutbound、ocrTimeoutMs、notifyPort、eventPollMs、asr
       · 存档：/Users/you/.dsh/weixin/config.json
       · 上次保存：5 分钟前
       想确认某一项到底有没有算数：改完发一条消息试试，或者用 /diag 看当前值。
```

- **大部分设置是热的**：热路径（限流、会话命令、提醒、主动开口、记忆、群聊、导出）每一处都重新读存档文件，所以白名单加人、改主动开口概率、开关记忆都是下一条消息就生效。
- **少数几项要重启**：ASR 子进程、通知服务的监听端口、长轮询与发送间隔、OCR 超时、语音外发——这些是插件加载时一次性建立的东西，改了不会自己重建。列在 `/config` 里就是为了不再靠猜。
- **这张表被测试盯着**：`test/config-effect.test.js` 拿 schema 的 107 个实际字段名逐字核对，漏一项、写错一个字都会红，而不是悄悄归进「保存即生效」。

## 假 iLink 测试工具包：一个假服务端，三份实现合成一份（1.2.0）

`test/fake-ilink.js` 是「假装我们是微信服务端」的唯一实现，`test/fake-ilink.test.js` 是它自己的
自测（10 条）。原来 `e2e` / `session-commands` / `markdown` 三个文件各写了一遍，细节还不一样：

- `e2e` 和 `markdown` 的空轮询一开始**立刻回 `[]`**，传输层于是变成忙循环（探针实测约 7000 次
  `getupdates`/秒），把进程里的定时器全饿住，一个文件的耗时从几秒变成一分钟；`session-commands`
  那份后来才补上 200ms 的挂起。同一个坑踩了两次 —— 现在只有一处能踩。
- 三份对 `getconfig` 的处理不同：一份在缺 `ilink_user_id` 时回 `ret: -2`（照抄真实服务端），另两份
  无脑回 `ret: 0`。

现在的接口：

```js
import { startFakeILink } from './fake-ilink.js'

const fake = await startFakeILink({ upload: true })   // upload: 也服务 getuploadurl
fake.deliver('你好', 'm1')                             // 排队一条入站文字
fake.deliver('打卡', 'm2', { groupId: 'room@chatroom' })
fake.failNext('/ilink/bot/sendmessage', { ret: -1 })   // 下一次发送失败（默认一次）
fake.outbound                                          // [{ text, body }]，每条发出的 chunk
fake.bodies                                            // 只给请求体的活视图（旧测试的 sent 形状）
fake.seen.uploads                                      // 每次 getuploadurl 的请求体
await fake.close()                                     // 连 keep-alive socket 一起关
```

要点：

- **空轮询会挂住 `EMPTY_POLL_HOLD_MS`（200ms）**，这是让整套 e2e 不空转的关键；
- `deliver()` 按 `message_id` 去重，「同一条消息被重投递」只有在测试想测时才发生；
- `bodies` 是**活**视图（Proxy），调用方在插件还在跑时就拿到的引用不会永远读到空数组；
- 脚本化时序用 `startFakeILink({ batches: [[...], [...]] })`：第 1、2 次 `getupdates` 各回一个数组，
  用完后回到 `deliver()` 的队列。

`markdown.test.js` 仍然保留自己的假服务端：它断言的是原始 `sendmessage` 请求体，而且流程是
「先起端口、再 apply、下一条轮询就要带上消息」。把它换成共享实现时，传输层会先看到一轮被拒的
`getUpdates`（`errcode=-14`），消息根本没到处理器 —— 这条写在该文件的注释里，免得下一个人重试同一件事。

## 知识库：把文件变成能引用的答案（1.3.0）

长期记忆管的是「这个人是谁」，知识库管的是「他给我的资料说了什么」。两者不能合并：记忆是模型
抽出来的一句话，知识库是原文，而**原文必须能指回出处**——用户拿它当凭据用（合同条款、退货政策、
保修期）。

### 用起来是什么样

```text
数据目录/knowledge/<账号>/
  after-sale.md
  保修条款.pdf
  公司报销制度.docx
```

放进文件、重启一次 DSH（或者等六小时内的下一次检查），然后：

```text
你：退货的运费谁出？
它：按《after-sale.md》· 退货政策，七天无理由退货，退货运费由卖家承担。
```

### 几个刻意的设计

- **不新增命令**。知识库是按目录约定的：放进去就生效，删掉就消失。命令是给愿意读文档的人用的，
  知识库要给「把文件丢给机器人」的人用。
- **切块带标题**。切块时跟踪最近的 `#` 标题，注入时说「《售后手册》· 退货政策」而不是只说文件名；
  相邻块重叠 60 字，一句话正被切断时仍能命中。
- **热路径只读索引**。检索在每条消息上跑，只读 `index.json`（几毫秒）；重建（读盘、抽 PDF）
  交给后台：启动一次、之后每 6 小时一次，另有「目录里有比索引新的文件」的廉价探测。
- **没命中就不花钱**。要求至少两个词面命中（或分数足够高）才注入，闲聊不触发。
- **明确禁止编造**。注入块里写着「资料里没有答案就直接说没写，不要编」——这是知识库跟
  「模型自由发挥」唯一的区别。
- **只看一层目录**。递归会让「把整个下载文件夹指过来」变成一场灾难。

### 拿不到的东西，写在这里免得有人再问

- 扫描件 PDF（纯图片）抽不出文字，会记一条 `no readable text` 跳过；要 OCR 得先走语音/图片那条
  OCR 桥。
- 不做向量检索：中文 bigram + BM25 在几十份文件的规模上足够，而且不需要额外模型与依赖。
- 不跨账号共享：每个账号一份目录、一份索引。

## 上手清单：新装之后先做哪几件事（1.3.0）

装好插件之后最常见的两个问题不是「坏了」，而是「没反应」（其实还没登录）和「它怎么不理我」
（其实白名单是空的）。上手指南不解释功能，只把这两件事排到最前面。

### 七步，但只有三步是必须的

| 步骤 | 必须？ | 为什么排这个顺序 |
| --- | --- | --- |
| 登录一个微信账号 | 是 | 扫码只能你本人做，没账号消息根本进不来 |
| 确认宿主版本在测试列表 | 是（能自动判断） | 版本不对时第一个症状是「莫名不响应」 |
| 决定谁能让它干活 | 是 | 它能在你电脑上读写文件、跑命令，白名单是唯一人为边界 |
| 选一个说话的样子 | 否 | 同一个模型换个语气像换了个产品 |
| 决定要不要主动找你 | 否 | 最容易「惊喜」的开关，明确一次比事后猜好 |
| 把资料交给它 | 否 | 知识库里放了文件，回答才会带出处 |
| 打开自动备份 | 否 | 记忆是这个插件最贵的东西，丢了重建不回来 |

「完成」只要求前三步；后面的永远显示成提示，不会变成待办——被清单追着走的人会关掉清单。

### 判断逻辑为什么不写在卡片里

卡片看得到的只是它自己那几个 remote 返回值，而「配好了没有」是跨组件的事实：有没有账号、
宿主版本对不对、白名单是不是空的、知识库有没有文件。所以判断放在 `src/onboarding.js`
（纯函数，输入什么答什么），卡片只渲染，测试也只测那一处。

一个细节：白名单**账号级**配置也算数。只看全局配置会骗人——只配了账号级白名单的用户
会一直看到「还没配」，然后去配一个自己并不需要的全局白名单。

### 命令行版为什么单独写一个脚本

`doctor.mjs` 回答「哪里坏了」，`onboard.mjs` 回答「我现在该做什么」。两者的排序原则相反：
doctor 把最可能出错的排前面，onboard 必须按「先做什么」排，而且没做的不该显示成红的。
硬塞进一个脚本，两件事都会做不好。

`onboard.mjs` 只读；它唯一的写操作是把 `knowledge/<账号>/` 建出来，因为用户看完清单的
第一个问题就是「文件放哪」。退出码 0/1 让它能当安装门槛用。

## 内置模板包：装完立刻像个样子（1.3.0-C）

「换个语气」不该先要求你填对一个 `packsIndexUrl`。远程索引是给分发自己模板的人用的；
第一次打开插件的人需要的是「点一下就能用」。

### 三个包，三种用法

- **贴心陪伴**：陪伴语气 + 早晚两条订阅 + 白天主动开口。给一个人用的场景。
- **办事助手**：先说结论、不寒暄、关表情关主动开口。给把微信当待办入口的人。
- **群聊主持**：`groupChatEnabled` + `groupReplyWhen: mention`，只在被叫到时说话。
  这个包特意**关掉主动开口**——一个既在群里活跃、又按时私聊你的机器人，很快就该被拉黑了。

### 包里能有什么，不能有什么

由 `src/packs.js` 的 `PACK_CONFIG_KEYS` 白名单决定：语气、节奏、主动开口窗口、日报时间、
免打扰时段、locale。**不在**白名单里的（白名单本身、媒体上限、模型路由、任何凭据）
永远不会出现在包里——这是安全边界，不是遗漏。

### 两个容易做错的地方

1. **装两次要无事发生**。导入是加法的：模式按名字去重、订阅按内容去重、配置只合并。
   一个装两次会重复的模板，用户就不敢点了。
2. **已经过去的每日订阅要顺延**。「每天 22:30 晚安」你在 23:00 装，如果照搬，下一秒就弹。
   `normalizePackForImport` 把已过的每日钟点改成「明天 HH:MM」，还把输入包复制一份不动常量。

### 为什么 preset 判断放在独立模块

`src/pack-presets.js` 只导出常量、清单和 `normalizePackForImport`；安装走的还是
`importPack` 那一条路（同一个校验器、同一套上限、同一种「只增」语义）。这样卡片的
「安装」按钮和手工粘贴 JSON 导入的是同一段代码，不存在两条会分叉的迁移路径。

## 回复迟到十分钟就发不出去（issue #9）

iLink 给每条入站消息配一张**回执票**（`context_token`），服务端只认它收到消息后十分钟内
的回执——十分钟一过，`sendmessage` 回 `prepare failed`。这个窗口不以我们的意志为转移。

原来的两种坏情况：

1. **答案写得太久**：模型思考串行发了十分钟，最后那句跨过窗口，前面一串 thinking 都收到了，
   唯独结论没有。这没法靠重试补——票会一直过期。
2. **重发队列白烧**：发送失败进 `outbox` 的那条，如果带着已过期的票重试，八次尝试全部注定失败，
   最后一条本来能换个时机发的消息也被判定为「发不出去」。

现在（`src/message/outbox.js` 的 `tokenExpired()` 与 `CONTEXT_TOKEN_TTL_MS = 8 分钟`）：

- 带票的条目超过 **8 分钟**就在 `flush` 里直接**停靠**，`lastError` 写
  `context token expired (…)`，不再调传输层、不再累加尝试次数；
- 没带票的条目不适用（它走会话路径或 typing-ticket 兜底，没有这个窗口）；
- 停靠不等于删除：`/outbox` 里还看得见，`/outbox drop <id>` 由人决定去留。

八分钟不是十分钟：留两分钟给时钟偏差和发送本身。

关于「模型思考超过十分钟」这件根因：那是回合长度的问题，`maxTurnWaitMs`（默认 5 分钟）
会先一步掐掉单个回合，所以正常路径下不会真走到第十一分钟；这条守卫是给「掐断之前就已经
跨窗口」的残余情况兜底——宁可少一次注定失败的尝试，也不要一条写着「发不出去」的死信。

## 借来的画：一条命令，把公开档案装进自己的表情包（本地）

内置那 68 张是我们自己画的；**别人的画**（权限允许你下载的那些）也可以用一条命令装进来。
第一个现成的包是「蓝色大肥鱼」档案里挑出来的 25 张：

```bash
node bin/stickers.mjs fetch bluefish --list   # 先看清单：名字、出处、权利
node bin/stickers.mjs fetch bluefish          # 装进 <数据目录>/stickers/all/
node bin/stickers.mjs fetch bluefish --limit 5 --mode girlfriend   # 只要前 5 张、只给女友模式
node bin/stickers.mjs fetch bluefish --force  # 已存在的重装
```

- **清单里没有图片**：`assets/sticker-packs/bluefish.json` 只有 `名字 + 出处(repo/path/sha) + 权利说明`。
  图片既不进仓库也不进 npm 包——档案页自己写着：它的 MIT 只覆盖**文字材料**，图片权利归各原作者，
  「以详情页的来源与授权为准」。所以取图这个动作发生在**你的机器上**：脚本走 `api.github.com` 的
  blob 接口（未登录每小时 60 次，一整套 25 张够用；`GITHUB_TOKEN`/`GH_TOKEN` 有就自动带上）。
- **装完就是普通的自定义表情**：名字即 `[表情:开心]`，同义词（`贴贴` → `害羞.png`）写进同目录
  `aliases.json`；目录列表按 mtime 失效，下一条消息就能发，不用重启。
- **webp/jpg 会转成 PNG**：机器上有装 Pillow 的 python3（脚本会自己找 `/usr/local/bin/python3.14`、
  `/opt/homebrew/bin/python3`、`python3`）就转，没有就原格式存下——原格式一般也能发。
- **离线/内网**：`--from <目录>` 用本地已经下好的同名文件代替网络，测试也走这条路。
- 名字怎么来的：档案里没有可读的标签（CMS 接口要登录、图里也没有 EXIF/XMP），
  所以是把 209 张预览按 12 张一页拼成**带编号的总览图**再逐页读图认出来的；少数名字可能和画面
  差一点，看到不顺眼的直接改名或删掉即可（**文件名就是表情名**）。
- 权利这件事不因为是「公开」就消失：这份清单是**给个人自己用**的便利，不要拿它去二次分发或商用；
  作者要求下架的话，删一个 json 条目就行。

## 回复风格反馈：不如直接告诉我（1.4.4）

提示词里那些风格规则（`src/message/human-pace.js`）是我们替所有人写死的：别写成公文、句子短一点、表情别滥用。但每个人要的不一样，写死的规则不可能都对。

所以加了一条最短的回路：**你直接说，它下一条就改**。

```text
/bad 太长了            这条回复哪里不好（最多 60 字）
/good 多用点表情        这条好在哪（同样 60 字）
/style                 看这个模式记下的偏好
/style clear           清空
```

几条设计上的取舍：

1. **下一条生效，不改历史**：反馈只影响之后的拼接，不回改已经发出去的内容，也不会去改写模式定义或记忆。
2. **按模式分开记**：女友模式里嫌「太客气」，不该带到工作助手的会话里；记的时候带上当时的模式 id。这里有一个例外：没带模式的老规则对所有模式都生效（它们本来就写在按模式分开之前的记录里）。
3. **只有最后 12 条、每条 60 字**：偏好记太多就不是偏好了，而且白占提示词。重复说同一件事不会堆叠，只把那条更新到最新时间。
4. **没有反馈就不占一个 token**：一条都没记时，提示词里连 `<style_feedback>` 这一段都不会出现——新装机器的成本是零。
5. **优先级写在块里**：这段明确写着「这是对方本人的要求，优先于上面对风格的通用描述」，免得模型把它当成又一个可选建议。
6. **不调模型**：`/bad`、`/good`、`/style` 全部是本地读写 `style-rules.json`，回复也不开会话。

状态文件：`~/.dsh/weixin/style-rules.json`，形如 `{schemaVersion, accounts:{<账号>:{rules:[{kind,text,modeId?,at}]}}}`。删掉这个文件就等于清空（也可以 `/style clear`）。

## 重要日子：提醒之外，先把那句要说的话拟好（1.4.4）

`dates.js` 从 0.9.15 起就在提醒「今天是她的生日」「三天后是结婚纪念日」。但真的到那天，卡住的不是「今天是什么日子」，是**那句要说的话**——于是提醒本身反而成了负担：看见了，还得现想。

现在提醒后面多一段草稿：

```text
📅 今天是重要日子
· 她的生日（第 2 年）

要不要发这句（`/draft send` 就发，`/draft` 换一句，`/draft skip` 算了）：
> 生日快乐！🎂 今天别忘了许愿。
```

三条刻意的取舍：

1. **不自动发**。替你把话说错，比不说更糟。草稿只是待发，`/draft send` 才出口——一个词的代价换「不发错话」。
2. **不调模型**。重要日子这条路从第一天起就是本地的（`dateReminderEnabled` 不花额度、不依赖网络），拟稿不破例：模板 + 你档案里的称呼。生日、纪念日、待办事件各有一套说法，`/draft 换一句` 换下一个说法。想让它自己写一句，在聊天里直接说就行。
3. **会过期**。草稿 36 小时内没人理就作废，免得下周手滑 `/draft send` 把上个月的祝福发出去。

`/draft` 本身也遵守「看和改是两回事」：不带参数只是把它念给你听，只有 `/draft 换一句` 才会重拟——不然你每次想看一眼草稿，都会把正要发的那句换掉。

状态文件：`~/.dsh/weixin/drafts.json`，一个账号一条，含 `text`、`forLabel`、`kind`、`conversationId`、`at`、`turns`。

## 主动开口的时机：从流水里学你几点出现（1.4.4）

主动开口原本只看配置：`proactiveWindowStart`–`proactiveWindowEnd`（默认 09:00–23:00）之内，每 5 分钟掷一次 35%。这套规则对「白天上班、晚上聊天」的人还算对，对凌晨两点才回消息的人就完全不对——白天它对着空气说话，深夜它已经收工了。

现在它多看一眼**消息流水**：把最近两周「对方发来的消息」按小时数一遍（`proactive-timing.js`），找出最活跃的连续 8 小时，把配置窗口**收窄**到那一段。

三条边界是刻意写死的：

1. **只收窄，不放宽**。配置窗口是硬边界。学出来的 `19:00–23:00` 只能让 14:00 不再开口，不能让 02:00 开口。
2. **两边不重合就照旧**。配置成 09:00–12:00、而这个人只在深夜出现时，模块什么都不改——宁可维持现状，也不要凭十来条样本把人静音。
3. **样本不够就不启用**。两周内少于 20 条入站消息、或覆盖不到 4 天，就当「还不认识你」。学习结果也不落盘：每次判断现算，删掉流水它就忘掉。

夜猫子会被学成一个**跨零点**的时段（比如 `22:00–03:00`）：它和配置窗口的重合部分可能落在一天的两端，两边都算数。

顺带把「被无视」的代价调重了：一次没回还是按 `2^miss` 退避（3 小时 → 6 小时），**连着两次没回**改成 `3^miss`（→ 18 小时，很快就撞上 24 小时封顶）。只是忙和真的不想被搭话，代价不该一样。

`/diag` 会多一行告诉你学到的时段或没启用的原因，例如：

```text
主动时段：19:00–23:00，覆盖 82% 的消息（43 条 / 11 天）
主动时段：样本不够（7 条 / 2 天），暂按配置窗口
```

## 群聊上下文摘要：被叫到时，知道大家在聊什么（1.4.4）

群里被 `@` 到时，模型看到的只有那一条消息。前面二十条说过什么、大家在约什么、谁在等谁回，全都在它的窗口之外——人不是这样参与群聊的。

打开 `groupSummaryEnabled`（**默认关闭**）之后：

- 每一条群消息都记进内存里的环形缓冲（最近 40 条），不管有没有被点到；
- 攒够 `groupSummaryEvery` 条（默认 12）就发一次后台调用，把这段群聊压成「不超过三句话：在聊什么、有哪些待办或约定、谁在等谁回」；
- 下次被叫到时，那几行作为 `<weixin_group_summary>` 折进提示词。

四条边界：

1. **默认关闭**。它每次都要花一次后台调用，静默花钱不是好默认；设置卡「群聊」组里有开关，统计页签的「群里在聊什么」一段会显示它占的提示词比例。
2. **摘要会过期**。默认 3 小时；更早的摘要不注入——昨天聊的事不该冒充今天的上下文。
3. **只复述，不发散**。提示词里写明「只写记录里出现过的信息，不要推测」，摘要上限 600 字符，防止它挤掉真正的上下文。
4. **原始消息不落盘**。环形缓冲只在内存里，重启后等新消息填回来；落盘的只有摘要本身与批次计数。

## 日报里的「昨天」：早上的那条能接上话头（1.4.4）

当天的日报从今天的流水来，但它现在多看一天：提示词里多一段**昨天回看** —— 昨天收到/发出多少条、聊得最多的那个会话、最后三句入站原话（各截 40 字）。昨天没有流水时这一段是空的，日报不会凭空提一句。

做这件事的理由是「接话头」：只讲今天的日报，早上那条读起来像一份报表；带上昨天最后几句，它就能顺着昨天没说完的事往下说。

怎么验证：`/digest` 现在就能看到（和 21:00 那条共用同一套提示词）；开着 `dryRun` 时连提示词原文都能打印出来核对。

## 群成员名片会过期：注明「可能已过时」（1.4.4）

群里的名片是「这个人说过的事」的快照。天天聊天的人，名片可能还是三个月前写的 —— 那时说的「最近在忙装修」，现在早搬完了。

所以名片现在记着**最后一次改内容**的时间（只是说话不算改），超过 `contactStaleDays`（默认 45 天）之后，注入时会多一行：

> 这张名片有 96 天没更新了，可能已经过时：别把上面的事当成现状。

不删、不改写：过时的事实仍然有用（知道这是谁），只是不能被当成现状。`/diag` 里会写「群成员名片：N 张（其中 M 张超过 45 天没更新）」。

## 本地语音：`/say` 与 `voiceReplies`（1.4.5）

`/say 晚安早点睡` → 一条音频。链路全在本机：macOS 的 `say` 合成 AIFF → `afconvert` 转 24 kHz 单声道 16 位 WAV → 插件自己的 SILK 编码器 → 发出去。**不联网、不需要 API key、不花钱**。

两条边界必须先说：

1. **不是某个人的声音**。本机只有系统音色（`say -v ?` 列出的那些）。要克隆谁的声音得接外部 TTS 服务（API key + 费用），本项目默认不做。
2. **机器人的语音气泡目前不被投递**。插件的 SILK `voice_item` 早就写好了，但 iLink 收下（`ret=0`）却不投递 —— 2026-06 与 2026-10-26 各测一次。所以 `/say` 默认发**音频文件**（一定送得到）；想试语音条就打开 `voiceOutbound`，失败会自动退回文件。

`voiceReplies` 打开后，陪聊模式下短于 `voiceReplyMaxChars`（默认 60 字）的回复会额外念一遍；合成失败只记一行日志，文字已经发出去了。

配置：`ttsVoice`（音色名，留空用系统默认）、`voiceReplies`（默认关）、`voiceReplyMaxChars`（默认 60）。

## `doctor --fix`：它能自己修的，就别让人动手（1.4.5）

`npm run doctor -- --fix` 先照旧跑 13 项体检（一个字都不变），然后打印一段 `fixed:`：

- 建出缺的插件目录（state root、`memory/`、`media/inbound/`、`knowledge/`、`backups/`，0700）；
- 把宽于 0600 的 `.json`、`openclaw-weixin/**`、`backups/**` 收回到 0600，把 owner 读不了/进不去的东西恢复成 owner 可读；
- 清掉超过 24 小时的 `*.tmp`（报告条数）；
- 顶层状态文件或账号文件坏掉时，改名成 `<名字>.broken-<时间戳>` 放在旁边 —— **不删**；
- 顺带一提不做的事：`instance.lock` 永不删（插件自己会接管陈旧锁），`asr-models/` 目录不扫（几百 MB 的第三方模型），`memory/**`/`journal/**` 里坏掉的 JSON 不动（那是用户内容，插件已经会降级为空）。

`-- --dry-run`（单独用或配合 `--fix`）只列 `would fix (dry run):` 什么都不改。所有能改的路径都从 state root 推导并做过 `path.resolve` 前缀校验；符号链接既不跟随也不改权限（手工验证过：指向 root 外的链接原样保留，外部文件的权限与字节未动）。

没有 `--fix` 时行为与以前逐字一致（测试里拿 `fixed:` 之前的输出做字节比对）。

## 群成员名片会自己补（1.4.5）

名片原来只有一个来源：群里被 @ 到、模型顺手把话记下来。结果是「天天聊天的人，名片还是三个月前写的」——1.4.4 让它注明「可能已过时」，但那只是提醒。

这一版做了另一半：**超过 `contactStaleDays`（默认 45 天）没更新过内容、且这个人最近 14 天在群里说过至少 3 句话**时，插件把他说过的原话交给后台模型，只从话里读出一张新名片（称呼/作息/喜欢/忌讳/重要日期），写回去。

三条自律：

1. **只补已经过时、又确实还在说话的人**：刚更新过的不动，久不出现的不猜；
2. **读不出来就留空**：提示词明写「不要编造没出现在话里的信息」，模型回空或读不出 JSON 就什么都不写；
3. **花的是后台预算**：整个流程走 `bridge.summarize`，因此受 `backgroundDailyLimit` 约束；每次最多 `contactRefreshPerDay`（默认 2）张，每 20 小时最多跑一次。

`instance.lock` 那种「每轮重试」的坑也避开了：跑完（包括「没得跑」和读流水失败）都记一次时间。
